# איסוף חבילות — אב־טיפוס

הפיצ׳ר מומש בענף `codex/pickup`, שנוצר מתוך `dev` ב־`c548ac6`.

## המסך והארכיטקטורה

- המסלול הקיים `/pickup` הוחלף במסך איסוף מלא בעברית וב־RTL. פריט הניווט הקיים משמש גם במחשב וגם בתפריט הנייד.
- Next.js 16 / React 19 / App Router, עיצוב CSS קיים, Lucide, מצב מקומי של React, pnpm ו־Vitest. קיים שרת Hono עם Drizzle; פיצ׳ר זה אינו פונה למסד נתונים. מנגנון ההתחברות מושבת בפרויקט כרגע.
- המסך מציג חבילות ממתינות, אחריהן מאושרות, ובתחתית סריקה והזנת מספר. סדר השורה נשאר תיבה מימין, תיאור במרכז ומספר משמאל גם ברוחב 390 פיקסלים.
- בחירה יחידה, בחירה מרובה, מצלמה, תמונה והזנת מספר משתמשות באותו חלון בדיקת תכולה ובאותו שירות אישור. זיהוי קוד בלבד לעולם אינו מאשר חבילה.
- החלון משתמש ב־`dialog.showModal()`, רקע לא פעיל, ניווט Tab מעגלי, Escape והחזרת מיקוד. בזמן שמירה סגירה ואישור נוסף מושבתים. המיקוד חוזר לאזור הראשי אם הכפתור המקורי הושבת אחרי האישור.

## נתונים וזהות

`client/src/lib/pickup/mock-collection.json` מכיל שני משתמשים בדיוניים ועשר חבילות עם מספר מוצרים וכמויות בכל אחת:

| מספרים | שיוך ומצב |
| --- | --- |
| 100001–100005 | משתמש הדגמה א, ממתינות לאישור |
| 100006–100007 | משתמש הדגמה א, כבר אושרו |
| 100008–100010 | משתמש הדגמה ב, לא זמינות למשתמש הנוכחי |

`getCurrentUser()` ב־`client/src/lib/pickup/current-user.ts` הוא מקור הזהות היחיד: `user-001`. השירות בודק שה־userId שנמסר הוא המשתמש הנוכחי, מסנן בעלות לפני חיפוש, ומאמת את כל מזהי החבילות לפני כתיבה. שינוי פרמטר userId אינו מאפשר מעבר למשתמש אחר.

`collectionService` ב־`client/src/lib/pickup/service.ts` הוא גבול הגישה לנתונים. המימוש אסינכרוני ומדמה השהיה קצרה. רכיבי המסך אינם קוראים את קובץ ה־JSON.

האישורים נשמרים במצב React וב־localStorage תחת `south-operation.pickup-confirmations.v1`, עם מזהה החבילה, מועד האישור וזהות המאשר. קובץ המקור אינו משתנה. שמירת אצווה היא כתיבה יחידה אחרי בדיקת כל הפריטים; כשל כתיבה אינו מוצג כהצלחה. בדפדפנים תומכים Web Locks מסנכרן אישורים בין לשוניות. אירועי storage מרעננים את הרשימות בלשוניות אחרות. ללא Web Locks אין הבטחת אטומיות בין לשוניות נפרדות; לשונית יחידה מוגנת מפני אישורים כפולים.

בסביבת פיתוח בלבד, `/demo/qr-generator` מציג איפוס לאישורי האיסוף. האיפוס משאיר את החבילות שנוצרו במחולל ואת האישורים המקוריים. אין כפתור איפוס במסך האיסוף.

## קודים וסריקה

- נעשה שימוש חוזר ב־`PackageCamera` וב־`CameraPreview` לניהול מצלמה, בהעדפת מצלמה אחורית ובמחולל `qrcode` הקיים.
- נוסף `@zxing/library` 0.23 לפענוח QR ו־Code 128. הסורק הישן ממשיך להשתמש ב־`qr-scanner`. הספרייה פועלת מקומית; לא נשלחות תמונות לשירות חיצוני. [תיעוד ZXing](https://github.com/zxing-js/library).
- QR: התחילית `PKG:` ואחריה 8–32 אותיות לטיניות גדולות או ספרות. דוגמה: `PKG:A7F3K9M2` עבור חבילה `100001`.
- Code 128: תוכן בן 13 ספרות בפורמט `729000` + מספר חבילה בן שש ספרות + `0`. דוגמה: `7290001000010`. זהו תוכן של Code 128, לא EAN-13; הספרה האחרונה אינה ספרת ביקורת EAN.
- מספר ידני: שש ספרות, הראשונה אינה אפס; רווחים בקצוות מוסרים.
- תמונות PNG/JPEG/WebP עד 10MB ועד 24 מיליון פיקסלים; פענוח מקומי מוגבל לרזולוציה של 1600 פיקסלים בצלע הארוכה.
- מזהי החבילות הקבועות תואמים למחולל הקיים. חבילות חדשות במחולל מצורפות למשתמש ההדגמה הנוכחי כממתינות לאישור, עם יחידה אחת מכל פריט. זהו קיצור דרך להדגמה בלבד, ולא מעבר סטטוס בשרת.
- המצלמה מבקשת הרשאה רק בעקבות לחיצה, ועוצרת לאחר קוד תקין, ביטול, מעבר עמוד, הסתרת הלשונית ויציאה מהעמוד. גם הרשאה שמגיעה לאחר סגירת החלון מטופלת ונעצרת.

## בדיקה ידנית

1. הריצו `pnpm dev` ופתחו `http://localhost:3000/pickup`. אם כבר בוצעו ניסויים, אפסו את אישורי האיסוף באזור הפיתוח במחולל QR.
2. סמנו `100001` ו־`100002`, לחצו על אישור החבילות שנבחרו ובדקו שכל תכולה מוצגת בקבוצה משלה. אשרו; שתי החבילות עוברות לרשימה המאושרת. רעננו את העמוד ובדקו שהאישורים נשמרו.
3. לחצו על אישור לפי מספר, הזינו `100003` ולחצו Enter. אותו חלון תכולה נפתח. נסו גם `100006` (כבר אושרה), `100008` (לא זמינה), `999999` (לא נמצאה) ומספר לא תקין.
4. במחולל QR בחרו חבילה ממתינה או צרו חבילה חדשה והורידו PNG. במסך האיסוף לחצו על סריקה והעלו את התמונה. ודאו שנפתחת בדיקת תכולה ושהחבילה טרם אושרה. אפשר גם להעלות תמונת Code 128 עם הערך המתאים.
5. לבדיקה במצלמה פיזית: הציגו את התווית במסך אחר או הדפיסו אותה. פתחו בטלפון את היישום דרך כתובת HTTPS מהימנה, לחצו על סריקה ואשרו הרשאה. אין להשתמש בכתובת HTTP של מחשב ברשת המקומית לצורך מצלמת טלפון; localhost במחשב אינו localhost בטלפון. בדקו סגירה, מעבר לשונית, חסימת הרשאה וסריקה חוזרת.

## בדיקות אוטומטיות ובדפדפן

- `pnpm lint` — עובר ללא אזהרות.
- `pnpm typecheck` — עובר לשרת וללקוח.
- `pnpm test` — 101 בדיקות עוברות, כולל שירות, הרשאות, אצווה אטומית, שמירה/שחזור/איפוס, מחולל קיים, מסכי אישור, שגיאות, מיקוד וניקוי מצלמה.
- בדיקות פענוח יוצרות פיקסלים אמיתיים של QR ושל Code 128 ומפענחות אותם בספרייה; הן אינן מסתפקות בהדמיית תשובת סורק.
- `pnpm build` — בניית production כוללת את `/pickup` ואת כל המסלולים הקיימים.
- `git diff --check` — תקין. לא קיים formatter מוגדר בפרויקט, ולכן לא נוספה תלות עיצוב חדשה.
- בדיקות דפדפן מקומי כוללות תמונות QR וברקוד, אישור מרובה, רענון, הזנה עם Enter, Escape, מיקוד, ניווט קיים ותצוגת מובייל ללא גלילה אופקית.

## גבולות האב־טיפוס

ההרשאות נאכפות בשירות הדמה, אך קבצי JSON וקוד לקוח אינם גבול אבטחה אמיתי: משתמש ששולט בדפדפן יכול לשנות את הקוד או האחסון. בגרסה אמיתית נדרשים התחברות, זהות מהשרת, בדיקות הרשאה בשרת וטרנזקציה במסד הנתונים. האישורים המקומיים אינם מסונכרנים בין מכשירים. צילום בטלפון פיזי, מיקוד עדשה ותנאי תאורה עדיין דורשים בדיקה במכשיר וב־HTTPS. נתוני המערכת הקיימים והשרת לא שונו.
